## Design conventions

- **Baseline:** Herdr 0.9.0 / protocol 22.
- **Tests:** focus on protocol-22 behavior; remove earlier-version compatibility expectations.
- **Migration:** replace superseded public shapes directly—no deprecated aliases or dual parsing paths.
- **Public inputs:** never require `_tag`. Prefer intention-revealing methods; when callers genuinely compose union values, use a domain discriminator such as `target`, `mode`, or `kind`. Keep Effect error tags and private state-machine tags internal to their appropriate boundaries.
- **Resource ergonomics:** callback-owned sessions are the default for interactive resources; streams own read-only subscription lifetimes. Explicit scoped acquisition is an advanced composition API, not required in normal examples.
- **Audit:** inspect all existing public inputs and resource APIs for these improvements during the 0.9.0 refactor; see section 19.
- **Examples below are proposed APIs**, not implemented code. Snippets assume `sdk` was obtained inside `Effect.gen`:

```ts
const sdk = yield * HerdrSdk;
```

Type sketches show the important shapes. Production types will come from Effect Schema, with encoded inputs parsed at service boundaries and branded domain values retained internally.

```diff
     shared compatibility check
       ping
-      require protocol 21
+      require protocol 22
     encode request

```

Keep the runtime guard; **do not build an earlier-version test matrix**.

### Change the types

```diff

+type HerdrProtocolVersion = 22;
```

`PingResult.protocol` remains an observed number. Decoding it directly as literal `22` would turn a protocol mismatch into a misleading malformed-response error.

```text
  superseded wire representations, where found

```


**Verification:** a protocol-22 fixture successfully exercises requests, event subscriptions, and graphics streams.

## 2. Workspace creation: choose intent through methods

Upstream permits both `cwd` and `source_workspace_id`, with `cwd` winning. We can eliminate this redundant, ambiguous combination through separate methods without losing meaningful behavior. Callers do not need to construct a directory union.

### Replace the public input shape

```ts
type WorkspaceCreateOptionsEncoded = {
  readonly focus?: boolean;
  readonly label?: string;
  readonly env?: HerdrEnvironmentEncoded;
};
```

Proposed signatures, each returning `Effect<WorkspaceCreateResult, WorkspaceOperationError>`:

```ts
create(options?: WorkspaceCreateOptionsEncoded, requestOptions?);
createInDirectory(cwd: string, options?: WorkspaceCreateOptionsEncoded, requestOptions?);
createFromWorkspace(sourceWorkspaceId: WorkspaceId, options?: WorkspaceCreateOptionsEncoded, requestOptions?);
```

These are signature sketches; `requestOptions` retains the existing typed transport request options. The boundary parses `cwd` as `HerdrAbsolutePath`, preserves established identifier evidence, and parses encoded options. No public `WorkspaceDirectorySelection` is needed. Reject obsolete `cwd`, `directory`, and `sourceWorkspaceId` fields in the options at runtime instead of silently ignoring them.

### Change the call stack

```text
WorkspaceService.create / createInDirectory / createFromWorkspace
  parse method-specific inputs
  construct one private creation intent
    default        → omit cwd and source_workspace_id
    directory      → send cwd
    from workspace → send source_workspace_id
  shared workspace.create dispatch and result decoding
```

The private intent can be a closed union for exhaustive encoding. It never appears in the public signature. Directory resolution remains server-owned. `createFromWorkspace` selects the source for the server's directory policy; it does not clone the workspace layout or session.

### Usage

```ts
yield *
  sdk.workspaces.createFromWorkspace(workspaceId, {
    label: "Review",
    focus: false,
  });

yield *
  sdk.workspaces.createInDirectory("/projects/herdr", {
    label: "Herdr",
  });

yield * sdk.workspaces.create();
```

**Delete:** the old creation input and the previously proposed public directory union. Replace their tests with method-signature inference, obsolete-field rejection, and exact encoding for all three methods.

Replace the proposed public `CommandTargetEncoded` union with explicit methods. Selection is only accepted for a pane target.

### Introduce the input types

```ts

};

  readonly expectedWorkspaceId?: string;
```

Proposed method shapes (request options omitted here for brevity):

```ts

      anchor: { row: 2, col: 0 },
      cursor: { row: 2, col: 24 },
      contentRevision,
    },
  });
```

**Delete:** the proposed public target union and generic target input. **Do not add:** arbitrary shell text, guessed command IDs, or automatic retries after `command_failed`.

## 11. Client-shell endpoint connection

This is the major new subsystem. It is **not** another newline-delimited JSON socket.

### Add the call stack

```text
ClientShellService.withConnection(input, use)
  create private Scope
  acquire through the same connectScoped implementation
    parse connection options
    acquire endpoint connection
    perform endpoint generation-1 negotiation
    validate selected snapshot/surface/input/blob codecs
    start scoped reader and routing workers
      read and decode binary envelopes
      route named controls
      assemble response chunks
      update projection/surface state
      process health probes
    await initial projection through the reader
  run use(connection)
  on success, failure, or interruption
    finalize workers, pending requests, socket, and buffers
  return callback result
```

### Proposed ownership

```text
src/
├── client-shell-service.ts       # callback-owned sessions and advanced scoped acquisition
├── herdr-endpoint-transport.ts   # connection, framing, correlation
├── herdr-endpoint-codecs.ts      # generation-1 wire encoding/decoding
├── herdr-client-shell-models.ts  # parsed public shell data
└── herdr-client-shell-state.ts   # pure revision/state transitions
```

The separate transport earns its place through different framing and connection-local resource ownership. Do not split this into a service for every message kind.

### Introduce the public types

```text
ClientShellConnectInput / Encoded
  surface dimensions
  cell pixel dimensions
  supported presentation/input settings
  connection deadline and bounded resource options

ClientShellConnection
  current projection
  projection stream
  surface operations and state
  semantic input operations
  endpoint-bound command/dismissal operations
  health/connection state
```

Default acquisition does not add a Scope requirement to the caller:

```ts
withConnection<A, E, R>(
  input: ClientShellConnectInputEncoded,
  use: (connection: ClientShellConnection) => Effect.Effect<A, E, R>,
): Effect.Effect<A, E | HerdrEndpointConnectError, R>;
```

The callback's error and environment requirements remain intact. This removes the _SDK connection's_ Scope requirement; it does not erase an unrelated Scope requirement introduced by the callback. Operations on the connection contribute their own errors through `E`.

Keep an explicitly named advanced API for callers who already compose scoped resources:

```ts
connectScoped(
  input: ClientShellConnectInputEncoded,
): Effect.Effect<
  ClientShellConnection,
  HerdrEndpointConnectError,
  Scope.Scope
>;
```

Both paths use one acquisition/finalization implementation, not parallel lifecycles. The callback defines how long the connection is useful. A caller can return or capture a handle in TypeScript, but using it after the callback ends must fail with `HerdrEndpointClosed`; the API does not pretend to statically enforce borrow lifetimes. Do not return lazy connection-bound streams for consumption after the callback.

For read-only consumers, add a cold `projections(input)` stream that owns acquisition during consumption and closes on completion, failure, or interruption. Each run opens its own connection. Layer-owned acquisition is an advanced application-composition option; do not hide an eagerly opened process-wide endpoint inside the ordinary SDK Layer.

### Introduce private wire types

```text
EndpointClientHello
EndpointServerWelcome
EndpointControl
EndpointRequestEnvelope
EndpointResponseChunk
EndpointPendingRequest
EndpointCodecSelection
```

These model upstream’s actual binary framing, boot identity, chunk ordering, and named controls—not invented JSON substitutes.

### Usage

```ts
const workspaces =
  yield *
  sdk.clientShell.withConnection(
    {
      surface: { columns: 100, rows: 30 },
      cellPixels: { width: 8, height: 16 },
      initialSurface: "inactive",
    },
    (shell) =>
      Effect.gen(function* () {
        const projection = yield* shell.snapshot();
        return projection.workspaces;
      }),
  );

// Read-only stream consumption owns its connection automatically.
const projections =
  yield * sdk.clientShell.projections(connectionInput).pipe(Stream.take(3), Stream.runCollect);
```

**Critical implementation gate:** complete the generation-1 codec/fixture mapping before claiming endpoint compatibility. A successful hello alone is insufficient.

## 13. Surface activation, frames, and patches

Replace the earlier simplistic active boolean with a state model that accounts for acknowledgement and presentation arriving separately.

### Introduce the state union

```ts
type ClientShellSurfaceState =
  | { readonly status: "inactive" }
  | {
      readonly status: "activating";
      readonly requestId: string;
    }
  | {
      readonly status: "awaitingSurface";
      readonly bootId: EndpointBootId;
      readonly projectionFloor: ProjectionRevision;
    }
  | {
      readonly status: "active";
      readonly bootId: EndpointBootId;
      readonly projectionFloor: ProjectionRevision;
      readonly surface: ClientShellSurface;
    }
  | { readonly status: "deactivating" }
  | { readonly status: "closed" };
```

Transitions and accepted data—not a caller-mutable status object—own this state.

### Add the call stacks

```text
shell.surface.set(active: true)
  serialize activation changes
  mark Activating
  send connection-local client_shell.surface.set
  await acknowledgement
  record projection revision floor
  mark AwaitingSurface
  accept matching complete surface
  mark Active
```

```text
incoming surface patch
  verify boot ID
  verify projection relationship
  verify base surface revision
  apply patch to current complete surface
  publish new surface
```

A patch without its base cannot be presented as valid. Use upstream’s resynchronization behavior, or close with a classified failure where recovery is unsupported.

### Introduce the data types

```text
ClientShellSurfaceSetInput
ClientShellSurfaceAcknowledgement
  active
  projectionRevision

ClientShellSurface
  bootId
  projectionRevision
  surfaceRevision
  terminal frame/cells/cursor
  pane geometry/content revisions
  split geometry
  optional popup
  graphics scene

ClientShellSurfacePatch
  bootId
  projectionRevision
  baseSurfaceRevision
  surfaceRevision
  changed rows/pane metadata/cursor

Supporting models
  SurfaceRevision
  SurfaceRect
  surface pane/scroll/split/popup records
  graphics asset key/source/format/placement/scene
```

### Usage

```ts
const acknowledgement =
  yield *
  shell.surface.set({
    active: true,
  });

// Separate operation: an ACK does not mean a surface has arrived.
const surface = yield * shell.surface.awaitReady();

yield * shell.surface.set({ active: false });
```

On ambiguous activation timeout/interruption, invalidate the connection rather than invent a confirmed state.

## 15. Error types and uncertain outcomes

### Refactor the failure call stack

```text
operation
  input failure             → HerdrInvalidInput
  socket/protocol failure   → transport/endpoint failure
  malformed response        → HerdrInvalidResponse
  server rejection          → HerdrServerError
  deadline                  → timeout
  interruption              → preserve interruption; finalize resources
```

### Type changes

```text
change
  HerdrUnsupportedProtocol                 # supportedProtocol: 22

retain
  HerdrInvalidInput
  HerdrInvalidResponse
  HerdrServerError
  ordinary request timeout/transport errors

introduce endpoint-specific tagged failures
  HerdrEndpointNegotiationError            # generation/codec negotiation
  HerdrEndpointTransportError              # connect/read/write/close
  HerdrEndpointRequestTimeout              # correlation + deadline
  HerdrEndpointClosed                      # use after closure
  HerdrEndpointUnsupportedMethod           # advertised-method check
  HerdrEndpointStaleReference               # wrong connection/boot
  HerdrEndpointInvalidMessage              # framing/chunk/revision violations
```

`HerdrEndpointConnectError` and per-operation error unions are **type aliases**, not additional wrapper errors. Each operation exposes only failures it can produce.

Preserve upstream error codes such as `stale_content` and `agent_prompt_stalled` inside `HerdrServerError`; no need for one class per server code.

### Usage

```ts
yield *
  sdk.panes.selection
    .read(paneId, selectionInput)
    .pipe(
      Effect.catchTag("HerdrServerError", (error) =>
        error.code === "stale_content" ? Effect.succeed(undefined) : Effect.fail(error),
      ),
    );
```

This example declines a stale selection; it does not retry against different text.

## 19. Public API ergonomics audit during the 0.9.0 refactor

### Decision rule

```text
inspect every public input and resource acquisition
  distinct caller action with different required data?
    prefer a named method with a primary positional input
  genuinely composable/recursive data?
    retain a union with a domain discriminator; use kind as fallback
  optional fields that allow ambiguity?
    split operations or enforce the relationship at the boundary
  caller acquires an interactive resource?
    callback-owned session by default; scoped acquisition for composition
  caller only consumes data?
    stream-owned acquisition
```

Audit `src/index.ts`, service signatures, model schemas/encoded aliases, constructors, inference tests, examples, and guides. Inspect schema-derived fields too, not only literal `_tag` declarations. Do not mechanically rename Effect error tags or private internal state tags. Public status outputs use `status`; public input unions never require `_tag`.

### Initial findings and implementation review targets

| Owner / surface                                                  | Decision or audit target                                                                                                                                                                          |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WorkspaceCreateInput` / `WorkspaceService`                      | Replace with `create`, `createInDirectory`, and `createFromWorkspace` sharing private dispatch.                                                                                                   |
| Proposed command target union                                    | Replace with `invoke`, `invokeInWorkspace`, `invokeInTab`, and `invokeInPane`.                                                                                                                    |
| `AgentTarget`                                                    | Already uses `kind` for pane/agent targets; inspect whether target-specific operations improve real call sites without multiplying the entire agent API unnecessarily.                            |
| `PaneMoveDestination`                                            | Review `moveToTab`, `moveToNewTab`, and `moveToNewWorkspace` as candidates; preserve direction/focus/result semantics. Do not add redundant wrappers without choosing one canonical public shape. |
| `PaneSwapInput`, `PaneInput`, `LayoutTarget`                     | Check alternatives and cross-field constraints; split distinct actions where simpler, otherwise retain domain unions.                                                                             |
| Worktree source and open inputs                                  | Audit workspace-vs-directory and branch-vs-path selection. Prefer named methods where they eliminate ambiguous inputs without creating a Cartesian product of methods.                            |
| Recursive `LayoutNode`, agent-view filters, event specifications | Retain composable unions with existing meaningful `type`/domain fields. One method per tree node/filter/event would make composition worse.                                                       |
| `PaneOutputMatch` and read modes                                 | Retain named match/read concepts where they are values composed into waits/subscriptions; do not replace every enum with methods.                                                                 |
| Endpoint semantic input and public lifecycle state               | Prefer semantic input methods; use `kind`/domain discriminators only for composed inputs and `status` for observable states.                                                                      |
| Graphics `openStream` / `openLayerStream`                        | Add callback-owned writer sessions using the existing scoped acquisition core. Review explicit `*Scoped` naming for advanced acquisition; no duplicate writer implementation.                     |
| `EventService.subscribe`                                         | Already stream-owned; preserve its no-manual-scope consumption and literal specification narrowing.                                                                                               |
| New client-shell connection                                      | `withConnection` for interactive sessions; `projections` for read-only streams; `connectScoped` for advanced composition.                                                                         |

The candidate rows are audit work, not a claim that every listed method split is already approved. For each selected change, record the exact old/new signature, call stack, input/result/error requirements, caller example, and smallest proving test alongside the implementation handoff. Remove superseded APIs rather than retain aliases.

### Acceptance

- No exported caller-authored input requires `_tag`.
- Method-specific types reject fields from another creation/target mode, with runtime boundary checks too.
- Protocol-22 tests exercise supported behavior, not earlier-version compatibility.
- Ordinary endpoint/graphics examples need no explicit `Scope` or `Effect.scoped`.
- Callback errors and requirements are preserved; SDK resource cleanup runs on every exit path.
- Escaped handles cannot keep sockets alive or operate after session closure; streaming resources close when consumption ends.
- No automatic global runtime, unmanaged background connection, or mandatory manual `close()` is introduced.

**The substantial new work is the endpoint transport and its complete data/lifecycle contract. The ordinary socket additions are much smaller. This remains a design proposal; no SDK implementation has been changed.**
